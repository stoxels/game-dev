# Passive Tree — Travel Node Design (working document)

Pure design, nothing implemented. Grounded in the current tree (364 nodes, 0 travel
nodes today) and the existing endgame stat sheet.

## What a travel node must be

A node qualifies as **travel** when all three hold:

1. **One line, no logic.** A single flat or percent bonus. No conditions, no
   procs, no new mechanics, no tradeoffs.
2. **Strictly superseded.** A sibling node elsewhere does the same thing but
   bigger — so taking the travel version is always the "cheap fill" option.
3. **Boring on purpose.** PoE 2's travel nodes are literally "+5 to an attribute
   of your choice". Their job is to make you *pay* for routing decisions, not to
   excite you.

Power guideline: a travel node should be worth roughly **20–30% of a comparable
notable** (PoE 2: +5 attribute on travel vs ~+30 on notable). Chainable in runs
of 3–4 before you reach a notable or keystone. If a travel node feels exciting,
it's a mis-tagged notable.

## 1. Existing nodes that could be re-tiered to travel

The tree already contains ~30 nodes that fit the profile above. Re-tiering is a
metadata change (`travel_` statKey prefix) — no new effects needed.

**QUESTIONS (study-time flats)** — pure +seconds, perfect travel:
`tick_tock_talent`, `second_hand`, `extended_session_1/2/3`, `midnight_oil`,
`wind_tunnel`, `jet_stream`.
Careful: `hourglass_doctrine` and `expected_shortfall` sound like tradeoffs —
verify before re-tiering; likely notables.

**ITEMS — the tier-1 of every 3-tier family** is a natural travel node, with
tier-2 = small and tier-3 = notable (the family *is* a PoE wheel, already built):
`stronger_light_1`, `stronger_marks_1`, `reinforced_ward_1`, `frugal_use_1`,
`quality_loot_1`, `bonus_replay_1`, `dampened_curse_1`, `seeker_of_light_1`, …
(~20 candidates). This one rule alone manufactures a full travel layer for the
south arm.

**PUZZLE — tier-1 of the grid families:** `streak_bonus_1`, `standard_deviation_1`,
the tier-1 start-reveal/mark flats, `residual_analysis_1`-style firsts.

**CLASSES — tier-1 of each acceleration pair:** `swift_strike`, `swift_marking`,
`swift_scan`, `quick_strike`, `rapid_revelation`, `hastened_zero` (their
`accelerated_*` siblings stay small/notable). Class gear nodes stay notables.

## 2. New travel nodes for the four categories

Shared idea first — the most PoE-like move available: **universal attributes**.
Our str/agi/int equivalent, drawn from the game's own fantasy:

- **PRECISION** — accuracy/quality side (feeds questions + item quality)
- **MOMENTUM** — speed/time side (feeds timers + class acceleration)
- **FORTUNE** — luck/probability side (feeds drops + procs)

Every travel node below can carry `+1..5` of one attribute instead of (or next
to) its concrete line. That gives the whole tree one shared language, lets
keystones reference attributes ("converts all Momentum into Fortune"), and makes
PoE 2's "+5 to any attribute" pattern trivially adoptable. Categories keep an
attribute identity: N=Momentum, S=Fortune, W=Precision (+class flavor), E=mixed.

**QUESTIONS (north):**
- `travel_study_time` — +N seconds question/exercise time (the flats above, re-tiered)
- `travel_rote_learning` — +N seconds per correct answer
- `travel_hint_quality` — +N% hint value/quality (small)
- `travel_answer_reward` — +N% rewards from correct answers
- `travel_tutor_patience` — +N% tutor effect duration
- `travel_curiosity` — +N% quest milestone rewards (bridges the quest-point economy)

**PUZZLE (east):**
- `travel_line_time` — +N seconds per line clear
- `travel_shield_ward` — +N% shield/freeze duration (tier-1 flats)
- `travel_grid_score` — +N% score multiplier (generic)
- `travel_start_reveal` — +N% chance of one extra start reveal (small)
- `travel_steady_hand` — +N% mistake penalty reduction (tiny, stackable)

**ITEMS (south):**
- `travel_drop_luck` — +N% item drop chance (the classic)
- `travel_item_quality` — +N% item quality
- `travel_use_time` — +N% item use duration
- `travel_curse_soften` — −N% curse severity (tiny)
- `travel_replay_fortune` — +N% replay trigger chance

**CLASSES (west)** — per-class generic fillers, mirroring how PoE class wheels
contain plain smalls alongside themed ones:
- Statistician: `travel_data_edge` — +N% strike/data effect
- Mathmagician: `travel_arcane_flow` — +N% echo/echo-duration
- Probabilist: `travel_sweep_breadth` — +N% sweep/marking effect
- Shared: `travel_gear_tuning` — +N% gear effect strength
- Plus a sprinkle of the universal attributes (Precision/Momentum/Fortune).

## 3. Combat travel nodes (5th system: endgame → later campaign)

> **Status: implemented as dev-only sandbox nodes.** 18 synthetic travel
> nodes (`travel_combat_*`, ids 403+, EN/DE text) on a ring of radius 600
> around Start in the dev tree, generated by
> `tools/generate-passive-tree-dev-data.py` (`COMBAT_TRAVEL_DEFS`). Wiring:
> 13 map directly onto existing endgame buckets, 3 defence lines are marked
> *pending* (need a global-defence hook — item-side flat defence mods are
> LOCAL by design), 2 economy lines (+shards, +XP) need a small gain hook.
> Values: +15 health, +10 mana, +2%/s regen, +10% heart-heal, +2 absorption
> on kill, +10% absorption regen, +5% earlier regen start, +4% attack speed,
> +3% move speed, +3% crit / +8% crit multi, +5% phys / +2–4 flat phys,
> +30 armour/evasion/+20 absorption (pending), +5% shards / +5% XP.

Grounded in stats that **already exist** in `endgame-player-stats.js`: health,
mana, life_regen, absorption_on_kill, absorption_regen_rate,
faster_absorption_reg_start, crit_chance, attack_speed, armour/evasion/
absorption, str/agi/int.

Structural idea: combat touches all four categories, so the combat arm works
best as a **ring around the center** (around the future Start/Ascendency node)
rather than a fifth outward arm — every category connects inward through it.
That also answers the earlier audit question about a 5th path: yes, but as the
center's crown, not a fifth spoke.

- `travel_flat_armour` / `travel_flat_evasion` / `travel_flat_absorption` — +N flat
- `travel_heart` — +N max hearts (flat health)
- `travel_regen` — +N% life regen
- `travel_absorb_on_kill` — +N% absorption on kill
- `travel_absorb_regen` — +N% absorption regen rate / faster regen start
- `travel_attack_speed` — +N% attack speed
- `travel_crit_edge` — +N% crit chance (small)
- `travel_raw_damage` — +N% increased damage (generic)
- `travel_toughness` — +N% reduced monster damage taken
- `travel_shard_harvest` — +N% shard gain from monsters (economy bridge → ITEMS)
- `travel_combat_xp` — +N% XP gain (leveling bridge → the future level-up point economy)
- `travel_str / travel_agi / travel_int` — +N attribute (literal PoE adoption; the
  stat pipeline already exists, so these are nearly free to wire later)

## 4. PoE 1 / PoE 2 patterns worth adopting

1. **"+5 to any attribute" travel (PoE 2).** Flexible fillers that smooth any
   path. Our version: `travel_any_attribute` — +N to one of
   Precision/Momentum/Fortune, chosen on allocation (or auto-assigned).
2. **Wheel rhythm (PoE 1).** ~3–4 travel nodes → 1 notable → keystone anchors
   the wheel. Our 3-tier item families already match this; formalize the ratio
   everywhere: **no notable is reachable in fewer than 2 travel nodes**.
3. **Keystones on wheel borders.** PoE places keystones where two clusters meet,
   so the interesting decision is *which side you approach from*. Keep
   KEYSTONES reachable from at least two category clusters; travel nodes form
   the borderlands.
4. **Small nodes near the start are stronger (PoE 2).** Teaches "invest near
   home". Early travel nodes slightly cheaper/stronger; outer travel weaker but
   feeding keystones.
5. **Travel counts toward thresholds (PoE 2).** Some effects count small
   passives; travel being a distinct tier matters for point math. For us: keep
   travel cheap (maybe half a point eventually) but *counted*, so pathing cost
   stays real as the tree grows.
6. **Jewel sockets as travel-layer milestones (both games).** Later: a special
   travel node type that grants a socket instead of stats — natural expansion
   once connections exist.

## Sizing sanity check

Current max points ≈ 84 (28 Convergence + 56 quest milestones). A PoE-like tree
of ~600 nodes at PoE's smalls:travel:notable mix (~60% travel) needs ~350+
travel nodes for full traversal — i.e., travel nodes are exactly what makes the
tree *cheap to grow*: they add size and pathing texture without new mechanics.
Until point income grows, keep travel cost-free-looking by making them dense
near notables rather than long chains.
